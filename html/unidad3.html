Unidad 3: Desarrollo de Aplicaciones Orientadas a Servicios

En esta unidad se identifican frameworks clave para construir aplicaciones orientadas a servicios y se describe el proceso completo para desarrollar una API robusta, segura y mantenible.

Competencias de la unidad:

  • Identificar frameworks backend, frontend y de integración para arquitectura orientada a servicios.
  • Aplicar un proceso estructurado de desarrollo de API desde el análisis hasta el monitoreo.
  • Usar buenas prácticas de seguridad, documentación y versionado.

Frameworks en aplicaciones orientadas a servicios

Un framework es un conjunto de herramientas y convenciones que acelera el desarrollo. En arquitecturas orientadas a servicios permite crear módulos desacoplados que se comunican por APIs.

  • Backend: Express.js y NestJS (Node.js), Laravel (PHP), Spring Boot (Java), FastAPI y Django REST (Python).
  • Frontend consumidor de servicios: React, Angular y Vue para integrar APIs REST/GraphQL.
  • Integración y mensajería: gRPC para alto rendimiento, RabbitMQ/Kafka para comunicación asíncrona.
  • Documentación y pruebas: OpenAPI/Swagger, Postman y Newman.

Ejemplo: API REST con Express

const express = require('express');
const app = express();

app.use(express.json());

app.get('/api/cursos', (req, res) => {
  res.json([{ id: 1, nombre: 'DWOS' }]);
});

app.post('/api/cursos', (req, res) => {
  const nuevoCurso = req.body;
  res.status(201).json(nuevoCurso);
});

app.listen(3000, () => {
  console.log('API activa en puerto 3000');
});

Proceso de desarrollo de una API

El desarrollo de APIs sigue un ciclo de vida para asegurar calidad, escalabilidad y facilidad de integración con otros sistemas.

  1. Análisis de requisitos: identificar consumidores, casos de uso y reglas del negocio.
  2. Diseño: definir recursos, endpoints, métodos HTTP, estructura JSON y códigos de estado.
  3. Seguridad: aplicar autenticación/autorización (JWT, OAuth2), validación y rate limiting.
  4. Implementación: construir controladores, servicios y acceso a datos.
  5. Pruebas: unitarias, integración y contratos de API.
  6. Documentación y versionado: OpenAPI, ejemplos, versión v1/v2 y estrategia de deprecación.
  7. Despliegue y monitoreo: CI/CD, logs, métricas, alertas y observabilidad.

Ejemplo: Seguridad básica con JWT (pseudo)

// Middleware de autenticación
function verifyToken(req, res, next) {
  const token = req.headers.authorization?.split(' ')[1];
  if (!token) return res.status(401).json({ error: 'Token requerido' });

  try {
    const payload = jwt.verify(token, process.env.JWT_SECRET);
    req.user = payload;
    next();
  } catch {
    res.status(403).json({ error: 'Token inválido' });
  }
}

Buenas prácticas para APIs orientadas a servicios

  • Usar nombres de recursos consistentes y rutas claras (ejemplo: /api/usuarios).
  • Responder con códigos HTTP correctos (200, 201, 400, 401, 404, 500).
  • Validar entradas en cada endpoint para evitar datos corruptos o inseguros.
  • Documentar ejemplos de request/response para facilitar integración de clientes.
  • Versionar la API para mantener compatibilidad con sistemas existentes.
